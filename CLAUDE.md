# Rove

A collaborative vacation planner. People create trips, invite others with a link, and plan together: day-by-day itinerary, ideas board with voting, budget, weather/news/map, and a home dashboard with a visited-places map.

- **Platform:** an **iPhone app** (Capacitor: the built web app inside a native iOS shell, `ios/`, bundle ID `com.adimenon.rove`). The website is deprecated: it still deploys and works as a test link, but nothing is designed or checked for desktop any more. Android later.
- **Test link (old live site):** https://adimenonworks.github.io/Travel-hub/
- **Owner:** learning to build apps. Explain what you change and why in plain language, and add a one-line explanation in brackets for any jargon.

## Publishing

- Any push to the repo's **default branch** builds and deploys automatically (`.github/workflows/deploy.yml`, about 1 minute). Other branches build nothing.
- A change is only live once it's on the default branch. **Publish every change by default**: once the build and checks pass and nothing needs the owner's attention (a rules re-publish, a decision, a known problem), open a PR, merge it and confirm the workflow run is green, without asking first. If something does need their attention, ask before publishing.
- Optional second host: Firebase Hosting at https://travel-hub-a1aa2.web.app runs only if the `FIREBASE_SERVICE_ACCOUNT` repo secret exists (see README).

## Stack

- React 19 + TypeScript + Vite. Hash routing (`/#/trip/:id`) because GitHub Pages can't route paths.
- Firebase Auth (Google sign-in) + Firestore, project `travel-hub-a1aa2`. The web config is in `.env.production`; it's public by design, and security comes from `firestore.rules`.
- **iPhone app:** `npm run ios` builds, copies into `ios/` (`npx cap sync ios`) and opens Xcode; run from Xcode on a phone. Sign-in in the app is native Google sign-in (`@capgo/capacitor-social-login`, pinned) handing its ID token to Firebase (`signInWithCredential`); it needs `VITE_GOOGLE_IOS_CLIENT_ID` in `.env.production` and the reversed client ID as a URL scheme in `ios/App/App/Info.plist`. `src/lib/native.ts` tells app from browser. Firestore keeps an offline cache on the device (`persistentLocalCache`). Pin new native packages to releases at least two weeks old.
- With no Firebase config (e.g. `npm run dev` without `.env.local`), the app runs in **demo mode** using localStorage. This is how to test locally.
- External APIs (free, no keys): Open-Meteo (weather + city search), OpenStreetMap/Leaflet (maps), Nominatim (address lookup). Fonts are bundled from npm: Manrope (`@fontsource-variable/manrope`) and Poppins Black (`@fontsource/poppins/latin-900.css`).

## Rules for changes

- **Figma is the source of truth:** file `cXoK1GzmzgqY0cmcgJw66W` (page "Foundations"). Token and component names in code match Figma 1:1: variable `interactive/button/primary/background` is `--interactive-button-primary-background`, text style "Heading 1" is `.t-heading-1`, primitives are `--color-emerald-300`, `--space-16`, `--radius-24`; the Layout collection is `space/default/500` → `--space-default-500` and `radius/600` → `--radius-600` (use these in components, not primitives). Figma's Typography collection has one mode (Small). Icons are Uicons Rounded in `src/design/components/icons.ts`, each with `state="default"` (line) and `state="filled"` (solid, brand colour). Components and screens live in the Figma sections "Components" (`88:7142`) and "Screens" (`337:8439`); never build from the archive section. Trip components are in `TripCards.tsx` (`HeroCard`, `TripHeader`, `BudgetCard` Planning/During, `DayCard`, `Timeline`); list and card components in `Rows.tsx` (`ListItem`, `ListGroup`, `SectionHeader`/`PageSection`, `EventCard` Standard/Journey/Note × Default/Next/Done, `TravelConnector`, `IdeaRow` + `VoteButton`, `Tile`, `QuickAction`, `MapCard`, `StatStrip`, `ProfileCard`, `OptionCard`, `SearchField`, `StepProgress`, `DestinationHeader`); flows in `Flow.tsx` (`FlowScreen`, `CelebrationScreen`, `Calendar`). `IconButton` is the Figma Icon button (40px, tones Secondary / Ghost / On brand). Avatars are 24 / 32 / 40; Avatar Stack uses 32. Nested corners: inner radius = outer radius − the gap, rounded down to a radius token (pills and circles exempt). Only phone sizes exist: the Large (744px+) variants, Card Type=Large, Avatar Large/Extra large and the Typography Large mode are on the Figma page "Archive — Large (deprecated)" and gone from the code (no `useLarge`, no width breakpoints). Button Small/Regular and 16/24px icons stay. Text styles in CSS use `font: var(--type-<style>)` (one token per Figma text style, in typography.css), never hand-typed sizes. Short tasks over a screen use the Figma `Sheet` (grabber, title + optional subtitle, close Icon button, content, full-width primary action); creating a trip is never a sheet. Short confirmations use the Figma Toast (`useToast()` from `src/design/components/Toast.tsx`): slides down from the top, stays 3 seconds, slides back up; `tone: 'error'` (status/error colours) when a save or delete fails. Saving, adding, deleting and copying all confirm with a toast. The map (Leaflet) and the /#/design page load on demand (`features/shared/Map.tsx`, `lazy` in App.tsx). Every page starts with the Figma Page Header (`PageHeader`): optional back button, the title (`size="large"`: Display 48 on tab pages; `size="small"`: Heading 1 on pushed pages) and an optional secondary icon button (edit). A trip's pages start with the `TripHeader`. Label / Label small are for controls only (Figma trims them to the cap height); stacked text uses body styles. Buttons: Size Regular is 32px (Label small, 16px icons), Large 48px (Label, 24px icons); variants Primary, Secondary, Destructive, Inverse (on emerald), Neutral, Tertiary (outlined, on accent surfaces), Ghost. Chips (`Chip`) are the country pills (Hero Card, Trip header) and open the Country sheet. Illustrations use only the one `--illustration-*` set (8 tokens; the per-surface sets are gone). The Bottom Nav uses `--elevation-floating-bar`. Never add or change anything that isn't in Figma: recommend it, the owner designs it, then build it. Change Figma first (or with the code), never only the code.
- **Design system:** bold, bright and rounded, inspired by Wise. `DESIGN.md` (repo root) is the Wise reference spec; follow it except where this file says otherwise. In short: pale neutral canvas (`--surface-background-primary`) with white cards, Poppins Black for page titles and big numbers only (`--font-display`, `--weight-black`), the Figma Hero Card (`HeroCard`, via `features/shared/TripHero.tsx`: phase-aware on one layout — the cover with a countdown Tag ("In 9 days", then "Day 3 of 10"), name, meta, avatars, country chips and one "next up" row: the next event, or "Add your photos" after the trip), Manrope everywhere else (`--font-family`), headings on one line (100% line height), one brand colour (emerald #2EE6B6) with its deep partner as text, pill-shaped controls and 24px card corners. Deliberate departures from DESIGN.md: emerald instead of Wise green, a dark mode, pill (not 24px) buttons and inputs, and WCAG AA contrast wins over any value in the spec. Colour: `primitives.css` holds seven palettes; emerald, green, orange, red, yellow and pink run 50/100–900, and white (0) and black (1000, #1c1c1c) exist only in neutral, which is pure grey (no brand tint). Each step sits at the same contrast against white; see-through steps are made with opacity in semantic tokens. **Colour is organised by the surface it sits on.** Each set is a Figma "Color" group and a CSS prefix: `on-light` (white `surface/primary`, light grey `surface/secondary`: canvas, cards, sheets), `on-mid` (bright emerald: Hero Card frame, accent cards, pins), `on-dark` (deep emerald: Hero Card panel), and `on-accent` (sparingly, for stand-out cards: surfaces `surface/yellow`, `surface/orange`, `surface/green`, `surface/pink`; the accents share one tone, so text, links, icons, borders, dividers and illustrations on top are shared). The base sets have the same names (surface primary/secondary/brand/sunken, text primary/secondary/brand, link default/hover/pressed, icon primary/secondary/brand, border subtle/bold/focus/brand, divider default, status ×6); on-accent matches them except its surfaces are named by colour and it has no status, so a component moves surface by swapping the set: e.g. `Card` tone Accent re-points every `--on-light-*` to `--on-mid-*`. Use the set for the surface an element actually sits on. Other groups: `--interactive-*`, `--tag-*`, `--input-*`, `--overlay-*`. Dark mode is the Figma Color collection's Dark mode (later: an extended collection; surface switching could become modes). Display text (page titles, the `t-display` style) uses `--on-light-text-brand`; other headings, body and form text are greys only. Emerald is for display titles, links, brand text and icons. Interactive states: hover is lighter, pressed is darker (`--interactive-*-hover` / `-pressed`). Categories have no colours: they're told apart by icon on `--on-light-surface-brand`. Never put text in a bright colour on a light background. Illustrations: one hand-drawn style for every empty state and trip cover (white framed shapes with the bold outline and a slight tilt, emerald land, warm sun, sparkle crosses), drawn in `src/design/components/Illustration.tsx` with semantic tokens only; `EmptyState` takes an `illustration`, never an icon. Use semantic tokens from `src/design/tokens/semantic.css` and components from `src/design/components/`. Never hard-code colors, sizes or radii. Add new tokens or components there and show them on the `/#/design` page (a builder's reference, deliberately not linked in the app's navigation; open it by URL).
- **Spacing:** pages are white (`on-light/surface/primary`) with 24px side margins (`--space-gutter`) and 96px (`--space-default-1000`) below every page.
- **Text size:** follows the person's iPhone text setting. `html { font: -apple-system-body }` (iPhone/iPad only; elsewhere a fixed 17px root) makes 1rem the iOS body size, 17px by default. Every type size is Figma px ÷ 17 in rem (`calc(14rem / 17)`), so at the default setting text is exactly the Figma size. Display and Heading sizes grow up to 1.4× (`min(calc(40rem / 17), 56px)`), like iOS large titles; body and label text keeps growing. Never type a font size in px. Anything holding text gets `min-height`, not `height`, and labels may wrap (buttons and list rows wrap). Size layout thresholds in rem (`minmax(calc(130rem / 17), 1fr)`, `flex-basis: calc(40rem / 17)`) so layouts reflow when text grows, not by screen width. Test at 17, 23 and 33px roots (default, largest standard, an accessibility size).
- **Responsive:** phone only, 320px (iPhone SE) to 430px (Pro Max); on a computer the test site shows a centred phone column (`--size-content-max` 480px). Tap targets ≥ 44px (a smaller control gets an invisible 44px area, e.g. the 32px header avatar), no horizontal scroll at 320px, light and dark mode.
- **Accessibility:** WCAG 2.2 AA. Text ≥ 4.5:1 contrast, control outlines and focus rings ≥ 3:1, never colour alone for state, every control has an accessible name. Check new colour pairs in light and dark mode, on every surface they can sit on.
- **Borders:** subtle (`--on-light-border-subtle`) by default; bold (`--on-light-border-bold`, `--input-field-border`) only for text inputs and where accessibility needs a visible outline. Lines between rows use `divider/default`. Links on light surfaces deepen on hover (lighter fails contrast).
- **App structure (Figma Screens):** Home = now (greeting, phase-aware Hero Card, quick actions). Trips = library (Segmented Control Upcoming · Past, "Plan a new trip", Hero Cards). You = profile (Profile Card, Your travels Stat strip + map, Favourite places, Settings list group whose rows open sheets, Sign out). A trip's Tab Bar: Overview (Budget card → Next up → Bookings tiles counting events by type → Good to know countries), Itinerary (Day Cards, Event cards joined by Travel connectors with an estimated walk/drive time from the two locations, the now Timeline), Ideas (To decide · Planned · Passed, Idea rows sorted by votes, tap for the idea sheet), Photos (album Cards), People (List group; owner taps someone to change role). Bookings tiles open `/trip/:id/bookings/:group`; an event opens its Event detail page (Event card, detail rows hidden when empty, files & links, comments). New trip is the full-screen flow (`features/trip/NewTrip.tsx`): Where to next? → When? (Calendar) → Who's coming? → Celebration. Not built yet (need data and design decisions): saving places (Saved segment, saved destinations, Save to Rove sheet, share extension), Recently viewed, flight status, currency conversion; see the handover doc's status list.
- **Features to keep working:** the trip's total budget (`trip.totalBudget`, group-wide) drives each day's budget (`src/features/trip/tripBudget.ts`: what's left, shared over the days to come; orange under half, red under a fifth). The Budget card shows Planning (trip cost so far: flights, stays, planned activities & food; spending money left) before and after the trip and During (today's planned spend of the day's budget) while it's on; its "Details" opens the budget sheet, where organizers edit days: each day row has a pencil; today and later days get their own budget (`trip.dayBudgets`), past days can correct what was spent (`trip.daySpent`, replaces the worked-out spend); the other days re-share what's left. Older trips only have `dailyBudget` (per person per day); keep saving it too. Every event needs a location: it adds the event's country to the trip's country chips (`tripCountries`). Events have six types (`EVENT_TYPES` in `src/lib/categories.ts`), one per Overview tile plus Note: Flight (Journey card: from, to, departs, arrives, flight number), Stay (one event with check-in `date` and check-out `endDate`; the itinerary shows it as check-in and check-out, `src/features/trip/events.ts`), Transport (Journey card when it has a from and to, else Standard), Food & drink, Activity, and Note (the only type without a place). Older values fold in via `eventType()`: cafe/drinks → Food & drink (keeping the Coffee/Cocktail icon), sight/other → Activity. "Add to itinerary" starts with the type list inside the Sheet, then asks only that type's fields. `eventCardProps()` in `events.ts` turns any event into its Event card. Rove doesn't track booked vs not booked. Country chips open the Country sheet (`CountryModal`): emergency numbers from `src/lib/emergency.ts` (only countries we're sure of) and a link to check entry requirements. Starred events (`activity.starredBy`, toggled on the event page) show in You → Favourite places and the collections (`/#/profile/collections/:key`, `favourites` = all starred).
- **Data:** UI code talks only to the `Store` interface. Any new data operation must be added to **both** `firebaseStore.ts` and `localStore.ts`. Dates are `YYYY-MM-DD` strings and times are `HH:mm`.
- **Security:** a new Firestore collection or field rule needs a matching change in `firestore.rules`, plus tests in `tests/rules/rules.test.mjs`. If the rules changed, the owner must re-publish them in the Firebase console. The owner isn't technical: never ask them to edit or add to anything. Paste the **entire** `firestore.rules` file in your reply as one code block, with numbered click-by-click steps (console.firebase.google.com → project travel-hub-a1aa2 → Firestore Database → Rules tab → select all and delete → paste → Publish). Make app code work with both the old and new rules, since they may publish later.
- Watch for `fn?.(await x())`: if `fn` is undefined, `x()` never runs. Await into a variable first.

## Feels like an iPhone app

- **Touch:** no zoom (viewport `user-scalable=no`; text still follows the iPhone text setting), no tap highlight or double-tap delay (`touch-action: manipulation`), presses respond on touch-down (a `touchstart` listener in `main.tsx` turns on `:active`), no page bounce (`overscroll-behavior: none`). Text isn't selectable and has no long-press menu, except fields and things people copy (addresses, notes, booking links, invite links: `user-select: text`). Menus and choices use native pickers (`<select>`, date and time inputs open iOS wheels); add `@capacitor/action-sheet` before building any custom menu. Haptics follow the Figma Haptics map via `haptic()` in `src/lib/native.ts`: selection (day strip, chips, calendar days, picking a destination), light/medium impact (votes, Option cards, favourites), success/error (trip created, failed); never for list taps, page changes or the Bottom Nav. Motion is concentrated in the New trip flow; Reduce Motion swaps slides, scales and confetti for fades.
- **Bottom Nav** (Figma "Bottom Nav" + "Nav Item"; `BottomNav` in `src/design/components`): Home (`/`: greeting, your upcoming trip, What's next, Banners), Trips (`/trips`: Your trips; also lit on a trip's pages) and You (`/profile`). It floats 16px from the sides and bottom, always on top; content scrolls under it (every page's 96px bottom padding clears it, plus the safe area). The selected pill slides between tabs; no haptic; tapping the current tab scrolls to the top. Shown on every signed-in page except Join and Design; hidden while the keyboard is open.
- **Navigation** (`src/app/navigation.ts`): links slide the new screen in from the right; back buttons (`PageHeader` back) step back through history (`goBack`) and slide the previous screen in from the left; Bottom Nav taps cross-fade quickly and return to that tab's own scroll position; the phone's own edge swipe-back switches without our animation. A trip's tabs are one screen (no slide). Each screen's scroll position is restored on back. Data hooks (`src/data/hooks.tsx`) keep the last value of every listener for the session, so a screen that opens again shows its data at once instead of flashing a skeleton.
- **Sheets** slide up and close by dragging their top down. The app doesn't resize for the keyboard (`resize: 'none'` in `capacitor.config.ts`): `setupNative()` puts the keyboard's height in `--keyboard-height`, a sheet focuses its first field as it opens and rises with the keyboard as one (CSS `translate`, the keyboard's timing).
- **Loading:** `PageSkeleton` / `Skeleton` (Figma "Skeleton"), never a spinner. The app opens from the on-device cache (Firestore offline cache, cached profile) before the server answers.
- **Native (iPhone app):** `RoveViewController` (in `ios/App/App/AppDelegate.swift`; `SceneDelegate.swift` makes it the root screen, and hands Google sign-in return links to `GIDSignIn`) turns on swipe-back and sets the light/dark canvas colour (white / #1c1c1c, the page colour) so nothing flashes white; the launch screen has a dark version. `setupNative()` in `src/lib/native.ts` keeps the status bar and keyboard in the app's theme, passes the keyboard height to CSS and hides the tab bar while typing. Sharing uses `shareLink()` (native share sheet). Invite links use `PUBLIC_SITE` in the app (the app's own address is `capacitor://localhost`).
- **Later:** push notifications (APNs, needs the Apple Developer Program), a Wise-style fourth tab once its page exists.

## Before pushing

1. `npm run build` (type-checks and builds).
2. Exercise the change in demo mode with Playwright (pre-installed, `require('playwright')`). Check 320, 375, 390 and 430px widths, light and dark mode, and large text (html font-size 23px and 33px).
3. If rules changed: `cd tests/rules && npm install && npm test` (needs Java; the Firestore emulator downloads on first run).
