# Rove design system: rules and components

**Read this before changing anything visual:** a component, token, icon, text style, colour or anything in Figma. `CLAUDE.md` has the short version of these rules; this file has the detail. `DESIGN.md` (repo root) is the Wise reference spec, and `docs/token-migration.md` records every token's old and new name (library v2).

**Moved word for word from `CLAUDE.md` on 14 Nov 2026,** when it was split (see `docs/DECISIONS.md`). Keep it current: when the app changes, update this file in the same pull request. If it disagrees with the code, Figma or `CLAUDE.md`, say so and fix whichever is wrong.

## Figma, tokens, components and names

- **Figma is the source of truth:** file `cXoK1GzmzgqY0cmcgJw66W` (page "Foundations"). Token and component names in code match Figma 1:1: variable `button/primary/background` is `--button-primary-background`, text style "Heading 1" is `.t-heading-1`, Base values (Figma collection **Base**, `base/color/emerald/300`) are `--base-color-emerald-300`, `--base-space-16`, `--base-radius-24` and are only used by other tokens; the Layout collection (one mode, "Value") is `space/500` → `--space-500`, `radius/600` → `--radius-600`, `radius/full` (pills), `space/page/*`, role sizes `size/*` (tap, icon, control, avatar, category-icon, tab-bar, content-max) and `border-width/*` (thin 1, medium 1.5, thick 2, focus 3); the Motion collection holds `duration/*` (Number, ms) and `easing/*` (String, the curve) → `--duration-quick`, `--easing-spring` in `src/design/tokens/motion.css`, with code-only `--motion-*` shorthands built only from them (no raw durations or curves anywhere else) (use these in components, never Base values). Figma's Typography collection has one mode (Small); Layout and Motion have one mode, "Value". Icons are Uicons Rounded in `src/design/components/icons.ts`, each with `state="default"` (line) and `state="filled"` (solid, brand colour). Components live in the Figma section "Components" (`88:7142`, page Foundations), laid out in rows by kind under a heading each: Controls · Navigation · Content & lists · Cards · Trip · People · Feedback · Media (a new component goes at the end of its kind's row; icons and flags are alphabetical grids in the Icons section, under Media); the core screens live on the **Screens** page (see Definition of done; sheets, flows and sub-pages aren't drawn). Never build from the archive section. Trip components are in `TripCards.tsx` (`HeroCard` (one component, no Size, a 5:2 cover everywhere since 13 Nov 2026; Show Avatar stack, Show heads-up, Show Tag (the countdown), Show Illustration, Show photo), `DayCard`, `NowLine` (Figma "Now line", called Timeline until 13 Nov 2026)); list and card components in `Rows.tsx` (`ListItem`, `ListGroup`, `SectionHeader`/`PageSection`, `EventCard` Standard/Journey/Note × Default/Next/Done, `TravelConnector`, `IdeaRow` + `VoteButton`, `Tile`, `QuickAction`, `MapCard`, `StatStrip`, `ProfileCard`, `OptionCard`, `StepProgress` (there is no Search field since 13 Nov 2026: it is a `TextField` with `icon`, Figma Text field "Show leading icon")); `Calendar` in `Calendar.tsx`; the New trip steps and the celebration are screens, not components (`FlowScreen`, `CelebrationScreen` in `features/trip/NewTripScreens.tsx`; the Figma "Flow screen" component was deleted on 13 Nov 2026, and the frames "New trip · step 1–4" and "New trip · celebration" on the Screens page show them); `Accordion` (Figma "Accordion": grey card, Heading 4 title, meta, chevron; State Collapsed/Expanded); `SegmentControl` (Figma "Segment control", renamed from Segmented Control on 11 Nov 2026: equal-width segments, the pill moves by transform only, never resizes; its label grows to 20px at most (1.4×) and its side padding shrinks from 16 to 8px as text grows; a label always stays on one line, never wraps (owner, 13 Nov 2026): when one doesn't fit its segment ("Collections", "To decide · 2" at 320px), the sides go to 8px and every label shrinks to fit, like iOS's shrink to fit, measured on the device, down to 80%; past that the counts (`count`) are dropped from view (still read out) and the labels shrink as far as they need). The **Logo** (Figma "Logo" component, from Logo explorations → App icon final: the walker R on an emerald tile; `Logo` in design/components, `src/assets/logo.svg`) is the app icon, favicon (`public/icon.svg`), home-screen icons, launch screen (centred on the page colour, light and dark) and the mark on the sign-in and Get Rove pages; never the old plane. `IconButton` is the Figma Icon button (40px, tones Secondary (grey) / Ghost / On feature (the New trip close button) / Primary (emerald, e.g. the comments Send button); the Page header's edit button is the grey Secondary). **List item** ends with Show trailing (text), Show Icon button (a small Ghost Icon button, e.g. Copy) or **Show Button** (a small Ghost Button, added 14 Nov 2026 for People's role dropdown, "Travelling ⌄"); with a Button or Icon button, the row wraps it under the text when there's no room beside it (large text), so a name is never squeezed. The **Context menu** opens under (or above) what was pressed and never runs past the page's side margins: at large text it's at most the screen width minus the margins, slid back inside them. Avatars are 24 / 32 / 40; Avatar stack uses 32. Nested corners: inner radius = outer radius − the gap, rounded down to a radius token (pills and circles exempt). Only phone sizes exist: the Large (744px+) variants, Card Type=Large, Avatar Large/Extra large and the Typography Large mode are on the Figma page "Archive — Large (deprecated)" and gone from the code (no `useLarge`, no width breakpoints). Button Small/Large and 16/24px icons stay. Text styles in CSS use `font: var(--type-<style>)` (one token per Figma text style, in typography.css), never hand-typed sizes. Short tasks over a screen use the Figma `Sheet`. **Edit sheets** (Edit event, idea, trip, album, a person's role; owner's pattern, 11 Nov 2026) use `mode="edit"` (Figma "Show save" + "Show discard"): Save is the Primary tick Icon button top-right in place of the close button, and the footer is "Discard changes" (Neutral) beside the optional Delete; creating something keeps the bottom Primary ("Add to Fri 13 Nov"); dragging down or tapping outside discards. The Sheet (it stops 24px below the status bar / Dynamic Island, and anything taller scrolls inside it; grabber, title + optional subtitle, close Icon button, content, then the footer, 40px below the content: the primary action, with "Show secondary action" (`secondary`, e.g. Delete) beside it half and half; buttons in a sheet never stack); creating a trip is never a sheet. Short confirmations use the Figma Toast (`useToast()` from `src/design/components/Toast.tsx`): slides down from the top, stays 3 seconds (6 with an action such as Undo, so there's time to reach it), slides back up; `tone: 'danger'` (status/danger colours) when a save or delete fails; `size: 'large'` (Body text, 24px icon, two lines, 6 seconds) for messages from people. Saving, adding, deleting and copying all confirm with a toast. The map (Leaflet) and the /#/design page load on demand (`features/shared/Map.tsx`, `lazy` in App.tsx). Every page starts with the Figma Page header (`PageHeader`): optional back button, the title (`size="large"`: Display 48 on tab pages; `size="small"`: Heading 1 on pushed pages) and an optional secondary icon button (edit; Figma "Show trailing"), with Show leading icon (the event page's category icon) and Show meta (a Body line under the title row). A trip's pages start with the Page header, Size Small with Show meta for the dates (the Trip header was merged into it on 13 Nov 2026). Label / Label small are for controls only (Figma trims them to the cap height); stacked text uses body styles. Buttons (Wise sizing): Size Small is 32px min (padding 6 / 12, Label, 16px icons) and the default; Large is 48px min (padding 12 / 20, Label, 24px icons) and the default only for full-width (`block`) buttons: sheet and flow footers, the big moments. A button keeps its height with or without icons; hover looks apply only on devices with a real pointer (`@media (hover: hover)`), since iPhone keeps :hover on a tapped button; Figma has no Hover variants since 13 Nov 2026 (Rove is touch-first: Button is Default / Pressed / Disabled, Text field Default / Focus / Filled, `.Tab` and `.Segment` Default / Pressed / Selected); the hover CSS stays in code only for the join-only website, which is used with a mouse; every button keeps a 44px tap area. Icon glyphs: Small (16px box) 12px, Large (24px box) 16px (`glyph()` in Icon.tsx; Figma's Icons match). Icon button has Size Small (32px, 16px icon), e.g. deleting a comment. Button variants: Primary, Destructive, Inverse (on emerald), Neutral (light grey `neutral-200` with dark text, `neutral-800` with light text in dark mode, since 11 Nov 2026: the everyday second button, quieter than Primary), Tertiary (outlined, on accent surfaces), Ghost. There is no Secondary (light emerald) button: the owner removed it on 10 Nov 2026 (weak on grey surfaces); use Neutral, or Inverse on emerald. Chips (`Chip`) are choice and filter pills (categories, cities, trips, collection filters); a selected category chip takes its type's colour. Illustrations use only the one `--illustration-*` set (7 tokens; `illustration/warm` was deleted in library v2). The Bottom navigation uses `--elevation-floating-bar`. **Names** (13 Nov 2026; the glossary is in `DESIGN.md` and on Foundations): sentence case everywhere; a "." in front of parts only ever used inside another component (`.Tab`, `.Segment`, `.Navigation item`, `.Calendar day`, `.Vote button`, `.Category icon`, `.Context menu item`); property names are only `Type` (event type), `Tone` (colour role; Button's old "Variant", code `tone`), `Size` (Small / Large, and Small / Medium / Large when there are three (library v2, 14 Nov 2026): Button `small` / `large`, Icon button `size="small" | "large"`, List item `small` / `large`, Avatar and `.Category icon` `small` / `medium` / `large`), `State` (a selected, checked or voted control is State=Selected, code `selected`), `Layout` and `Show <thing>` (library v2: when the thing is one component, its name as written, "Show Icon button", "Show Avatar stack", "Show Tag"; otherwise sentence case, "Show meta", "Show leading icon"). Full names, not abbreviations (Information, Document, Sign out, Bottom navigation, Coach, Campervan); every layer name starts with a capital. The in-page message is the **Banner** (code `Banner`, Tone Warning / Success / Danger / Neutral / Accent; "Notification" is kept for the Notification centre). **Figma is the source of truth for components.** A new or changed component, variant, token or icon is built in Figma first, then in code, and they always match exactly. Only the eight core screens are drawn in Figma, and their frames are updated when they change in code; sheets, flows and sub-pages aren't drawn (see Definition of done in `CLAUDE.md`). Icons the owner wants added are dropped in the "Backup icons" section on the Figma page **Backup artifacts** (moved there from Foundations on 13 Nov 2026); move them into the Icons component (every size and state) and `icons.ts`.

- **Who's in (14 Nov 2026, people and sharing item 3):** Chip has **Show Avatar** (a Small Avatar before the label; code `avatar`, plus `pressed` for toggles). New component **Who's in row** (`689:1458`; code `WhosInRow`): a Body small secondary label and a wrap of avatar Chips, 8px gaps; selected = in. **Event card** has **Show footer** (an Avatar stack and the **Going** text, "2 of 4 going") and **Show Button** (a small Neutral Button, Inverse on the Next card: I'm in / I'm out); code `people`, `going`, `action`. With a Button the card is a box with an invisible link over it and the Button above the link, since a button can't sit inside a link.

## Visual design, colour and illustration

- **Design system:** bold, bright and rounded, inspired by Wise. `DESIGN.md` (repo root) is the Wise reference spec; follow it except where this file says otherwise. In short: white canvas (`--surface-primary`) with light grey cards (`--surface-secondary`), Poppins Black for page titles and big numbers only (`--font-display`, `--weight-black`), the Figma Hero card (`HeroCard`, via `features/shared/TripHero.tsx`: phase-aware on one layout — the cover with a countdown Tag ("In 9 days", then "Day 3 of 10"), name, meta, avatars and an optional heads-up row ("Check-in open", "Check the entry requirements"); no next-up row since 11 Nov 2026), Manrope everywhere else (`--font-body`; Figma `font/body`), headings at 125% line height (Display, Heading 1 and Heading 2, since 11 Nov 2026, so wrapped titles never touch), one brand colour (emerald #2EE6B6) with its deep partner as text, pill-shaped controls and 24px card corners. Deliberate departures from DESIGN.md: emerald instead of Wise green, a dark mode, pill (not 24px) buttons and inputs, and WCAG AA contrast wins over any value in the spec. Colour: `primitives.css` holds nine palettes; emerald, green, orange, red, yellow, pink, sky and violet run 50/100–900 (sky, hue 232°, and violet, 295°, were added on 11 Nov 2026 for the event type colours), and white (0) and black (1000, #1c1c1c) exist only in neutral (no colour palette has a 1000), which is pure grey (no brand tint). Each step sits at the same contrast against white; see-through steps are made with opacity in semantic tokens. **Colour is one set for every surface** (library v2, 14 Nov 2026; old → new names in `docs/token-migration.md`): the Figma Color collection (modes Light and Dark) holds `surface/*` (primary, secondary, sunken, brand), `text/*` (primary, secondary, brand, link, link-hover, link-pressed), `icon/*`, `border/*` (subtle, bold, focus, brand, divider), `status/*` (success, warning, danger, each with `-subtle`), `button/<tone>/*`, `control/*` (selected, selected-ghost, unselected, unselected-ghost: chips, tabs, segments, day cards), `input/*`, `tag/*`, `category/*`, `overlay/*`, `illustration/*` and `map/pin`, `map/pin-icon`. **Feature surfaces** (deep green: the Next Event card, the accent Card, the Stat strip, Avatar initials, your chat bubbles, the New trip flow and celebration) use the `feature/*` tokens directly (surface, surface-secondary, surface-sunken, text, text-secondary, icon, icon-secondary, border-subtle, divider, border-focus, status-warning); nothing re-points other tokens, and the one shared rule is the focus ring on a `.feature` element. Display text (page titles, the `t-display` style) uses `--text-brand`; other headings, body and form text are greys only. Emerald is for display titles, links, brand text and icons. Interactive states: hover is lighter, pressed is darker (`--button-*-background-hover` / `-pressed`, `--control-*`). **Event types have colours** (owner's choice, 11 Nov 2026, "Option D"), everywhere an event or saved place shows, so a type, its colour and its icon go together: only on the icon tile, a solid colour with a white icon (dark mode: the 300 step with a near-black icon), via `--category-<type>-surface` / `-icon` (Figma Color → `category/*`): Getting around (flights included) sky, Stays violet, Food & drink yellow, Activities pink, Notes & reminders emerald; Free time stays neutral (the white tile). On the deep-green Next card the tile takes `--category-<type>-surface-on-feature` / `-icon-on-feature` (the 300 step, near-black icon, in both modes). `categoryTone()` / `TYPE_TONE` in `src/lib/categories.ts` give an event's colour, `placeCategory(c).tone` a Place's. The type and its colour live only in the Figma **`.Category icon`** (`CategoryIcon`: Type × Size Small 32 (16px icon) / Medium 40 / Large 48 × Tone, the surface it sits on, which only changes the Neutral tile: Secondary (grey, on white), Primary (white, on a grey card), On feature (the Next card, where colours take the 300 step)); Event card (Layout × State only), List item, Idea row, Option card (Layout Plain / Category: Category puts the tile 16px above the text, the Add to itinerary picker) and the Page header nest it as an exposed instance, and pass the event type as `type` in code (13 Nov 2026); Chip is the one exception that keeps "Type" (code `type`): an active category chip takes the colour (step 2 of Add to itinerary, the save and place sheets). It's used by the Itinerary, Next stop, Home's Next up and the Hero card's heads-up row, Overview's Bookings and Recently viewed rows, the Budget card's row icons, Ideas, Collections, Favourites, Home's Recently saved and New trip's Bring your saves. Cards stay grey and the icon still tells categories apart (never colour alone). Never put text in a bright colour on a light background. Illustrations (one Figma set, "Illustration", Size Spot / Cover, with `Name` for which drawing: the one property name outside the glossary; code `name`, covers are `cover-*`): one hand-drawn style for every empty state and trip cover (white framed shapes with the bold outline and a slight tilt, emerald land, warm sun, sparkle crosses), drawn in `src/design/components/Illustration.tsx` with semantic tokens only; an empty state is a `Card` with `layout="centre"` and an `Illustration` in `media`, never an icon (the Empty state component was merged into Card on 13 Nov 2026; Figma Card has Tone Default / Accent × Layout Start / Centre, Show media, Show body, Show actions). Use semantic tokens from `src/design/tokens/semantic.css` and components from `src/design/components/`. **Every value comes from a variable** (owner's rule, 14 Nov 2026): in Figma, every colour, spacing, corner, size, border width and text value inside a component is linked to a variable or style (screen frame widths on the Screens page are canvas layout, not component values); in code the same, through CSS variables: colours from Color, spacing and corners from Layout, fixed sizes from the role sizes (`size/tap`, `size/icon-*`, `size/control-*`, `size/avatar-*`, `size/category-icon-*`, `size/tab-bar`, `size/content-max`) or else the numbered scale `size/{step}` (100 = 4, 200 = 8, 400 = 16, 500 = 20, 600 = 24, 650 = 28, 700 = 32, 750 = 36, 800 = 40, 900 = 48, 1000 = 56, 1050 = 60, 1100 = 64, 1200 = 72, 1300 = 96, 1400 = 112, 1500 = 120, 1600 = 176, 1700 = 240, 1800 = 440, 1900 = 560; no one-off component size tokens), line widths from `border-width/*`, timings from Motion, or a `calc()` of those (e.g. a 44px tap area around a 32px control is `calc((var(--size-control-small) - var(--size-tap)) / 2)`). The allowed exceptions: sizes that grow with text, written `calc(Nrem / 17)` (owner, 14 Nov 2026); `0`; media query widths (CSS can't use variables there); numbers passed as component props (icon and illustration sizes, a map's height); and artwork (the Logo's colours, the Illustration drawings). Add new tokens or components there and show them on the `/#/design` page (a builder's reference, deliberately not linked in the app's navigation; open it by URL).
